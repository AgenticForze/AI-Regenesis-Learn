## TL;DR

Most real-world machine learning problems are data problems, not algorithm problems. Before any
model in chapter 1.5 can be trained, raw data has to survive a pipeline: cleaning, encoding,
scaling, and validation, each stage capable of silently corrupting what the model eventually
learns. Feature engineering turns raw fields into model-ready inputs. Data quality issues, missing
values, duplicates, and mismatches between how a feature is computed for training versus serving,
degrade a model without ever throwing an error, which is exactly what makes them dangerous.

## High-Level Explanation

A production data pipeline moves raw data through several stages before it ever reaches a model:
ingestion from source systems, cleaning (deduplication, outlier handling), feature engineering
(the transformations covered in this chapter), validation, and finally delivery to training or, in
production, to a live model making predictions. A failure at any stage propagates forward silently,
because a pipeline that runs without crashing gives no signal that its output is wrong.

**Feature engineering** covers three recurring jobs. Encoding turns categorical values (a merchant
category, a diagnosis code, a device type) into numbers a model can use: one-hot encoding creates a
binary column per category, ordinal encoding assigns an integer (appropriate only when the
categories have a genuine order), and target encoding replaces a category with a statistic of the
target variable within that category, which is powerful but has a specific leakage risk covered in
the Deep-Dive. Scaling puts numeric features on comparable ranges, which matters for
distance-based methods like k-NN (chapter 1.5) and gradient-based training, but not for
tree-based splits, which only compare values within one feature at a time. Handling missing values
means deciding whether to drop, impute, or explicitly flag a gap, a decision that depends on why
the data is missing in the first place.

**Data quality** is usually described along a few practical dimensions: completeness (how much
data is missing), accuracy (does the recorded value match reality), consistency (does the same
entity look the same across sources), and timeliness (is the data current enough to be useful). A
pipeline that looks healthy on every one of these dimensions can still fail in a way none of them
catch: training-serving skew, where a feature is computed one way when a model is trained offline
and a subtly different way when the same model serves live predictions, so the model sees data at
serving time that does not match what it learned from.

## Deep-Dive Explanation

**Missing data, formally.** Missing values fall into three categories that determine which
handling strategy is valid, a taxonomy generally attributed to Rubin's work on statistical
inference with missing data (Little and Rubin,
[*Statistical Analysis with Missing Data*](https://onlinelibrary.wiley.com/doi/book/10.1002/9781119013563),
2nd edition, Wiley, 2002). Missing Completely at Random (MCAR) means the chance a value is missing
has nothing to do with any variable, observed or not, so simple approaches like dropping rows
introduce no bias, only lost data. Missing at Random (MAR) means the chance of missingness depends
on other observed variables (a customer's income is more often missing for a specific channel that
also happens to be recorded), which model-based imputation can account for. Missing Not at Random
(MNAR) means the chance of missingness depends on the missing value itself (sicker patients are
more likely to have a lab value recorded at all, precisely because they are sicker), which no
imputation method can fully correct without external information, because the data needed to
correct it is exactly what's missing. Common imputation strategies range from mean or median
imputation (simple, but can distort variance and correlations), to Multiple Imputation by Chained
Equations (MICE), which models each incomplete feature as a function of the others and repeats
across several imputed datasets to represent the remaining uncertainty (van Buuren and
Groothuis-Oudshoorn,
[*mice: Multivariate Imputation by Chained Equations in R*](https://www.jstatsoft.org/article/view/v045i03),
*Journal of Statistical Software*, 2011). A missingness indicator column (a binary flag for "this
value was imputed") is frequently added alongside any imputation, since the fact that a value was
missing can itself be predictive. Critically, imputation statistics (the mean, the MICE model)
must be fit on the training split only and then applied to validation and test, exactly the same
data leakage boundary from chapter 1.4: fitting an imputer on the full dataset lets validation and
test information leak into training.

**Categorical encoding, formally.** One-hot encoding represents a category with k values as k
binary columns, which is safe but expands dimensionality fast for high-cardinality features (a
diagnosis code set with thousands of values). Ordinal encoding instead maps each category to a
single integer that preserves a rank (Low, Medium, High, Premium becomes 0, 1, 2, 3), which is
compact but only valid when that rank genuinely exists in the data; applied to a category with no
true order (a merchant type, a device model), it introduces a spurious distance relationship, a
model reading the integers as if the categories were evenly spaced along one axis, that isn't
actually present in the underlying data. Target encoding (also called mean encoding) replaces
a category with the mean of the target variable observed for that category, which is compact and
often effective but leaks label information directly if computed on the same rows it's applied to;
the standard mitigation is to compute it out-of-fold (using a cross-validation-style split so no
row's own label ever contributes to its own encoded value) and to blend the per-category mean with
the global mean when a category has few observations, so rare categories don't get an
overconfident, high-variance estimate (Micci-Barreca,
[*A Preprocessing Scheme for High-Cardinality Categorical Attributes in Classification and Prediction Problems*](https://dl.acm.org/doi/10.1145/507533.507538),
*SIGKDD Explorations*, 2001). Learned embeddings, low-dimensional dense vectors trained alongside a
neural network, are a common alternative for very high-cardinality categoricals, letting the model
discover which categories behave similarly rather than requiring that to be specified in advance
(Guo and Berkhahn,
[*Entity Embeddings of Categorical Variables*](https://arxiv.org/abs/1604.06737),
arXiv, 2016).

**Feature scaling, formally.** Standardization rescales a feature to x' = (x − μ) / σ, giving it
mean 0 and standard deviation 1; min-max normalization rescales to x' = (x − min) / (max − min),
mapping values into [0, 1]. Both are fit on the training split only, for the same leakage reason as
imputation. Scaling changes the numeric geometry a distance calculation or gradient descent step
sees, so it materially affects k-NN, SVMs, and gradient-based linear and logistic regression
(chapter 1.5), but leaves tree-based splits unaffected, because a split threshold on one feature is
invariant to a monotonic rescaling of that feature.

**Training-serving skew, formally.** A model is trained on features computed by one code path,
often a batch job running over historical data, and served by a different code path, often a
real-time service computing features from a live event stream. If the two code paths compute
"the same" feature even slightly differently, for example a rolling 30-day average computed with a
different window-alignment rule, the trained model receives inputs at serving time that don't match
the distribution it learned from, degrading performance in a way that offline evaluation metrics
(chapter 1.6) cannot detect, because offline evaluation runs entirely inside the training-side code
path. This is a well-documented, specific instance of a broader pattern in which the ongoing
maintenance cost of a machine learning system is dominated by the surrounding data infrastructure
rather than the model itself (Sculley et al.,
[*Hidden Technical Debt in Machine Learning Systems*](https://proceedings.neurips.cc/paper/2015/hash/86df7dcfd896fcaf2674f757a2463eba-Abstract.html),
*NeurIPS*, 2015). The standard mitigation is a shared feature-computation layer, often called a
feature store, used by both the training pipeline and the serving path, so "the same feature" is
guaranteed to mean the same code rather than two independent implementations kept in sync by hand.
