## TL;DR

A model trained on data that reflects historical or societal bias reproduces that bias, and can
amplify it through feedback loops that neither an accuracy metric nor a training log will surface.
Fairness is not one property a model either has or lacks: there are several mathematically
reasonable definitions of "fair," and when groups have different base rates, some of the most
natural ones are provably impossible to satisfy at the same time. Explainability closes the loop by
giving stakeholders, developers, auditors, and the people a decision affects, a way to see why a
model produced a specific output, which is necessary for debugging, trust, and increasingly, for
regulatory compliance.

## High-Level Explanation

**Bias** enters a machine learning system long before training starts. Historical bias means the
data accurately reflects a real-world process that was itself discriminatory, so a model trained on
it learns the discrimination as a valid pattern. Representation bias means some group is
underrepresented in the training data relative to the population the model will actually be applied
to, so the model has less signal to learn that group's patterns from. Measurement bias means a
feature or label means something different across groups even though it is recorded the same way,
often because it is a proxy for what actually matters rather than a direct measurement of it. Label
bias means the labels themselves, frequently generated by human annotators or by another biased
process, encode the same distortions the model is meant to avoid learning. These are not
theoretical concerns: a model can pass every accuracy check on an aggregate test set while
performing substantially worse for a specific subgroup, and nothing in a standard evaluation report
(chapter 1.6) is designed to surface that on its own.

**Fairness** asks a harder question than "is this model accurate," because there are several
distinct, individually reasonable ways to define "fair," and they do not all agree with each other.
Demographic parity asks whether a model's positive prediction rate is the same across groups.
Equalized odds asks whether the model's true positive rate and false positive rate are each the
same across groups, a different and often incompatible standard. Predictive parity (also called
calibration) asks whether, among people the model scored the same way, the actual outcome rate is
the same across groups. Choosing which of these to optimize for is a policy decision informed by the
specific harm being guarded against, not a purely technical question with one correct answer.

**Explainability** is the practice of making a model's output legible to a human. Some models are
intrinsically interpretable: a linear regression's coefficients or a shallow decision tree's split
path can be read directly, at some cost to how flexible the model can be. For models too complex to
read directly, post-hoc explanation methods approximate why a model produced a specific output
without requiring the model itself to be simple. A local explanation covers one specific prediction
(why was this loan application declined); a global explanation summarizes the model's behavior
overall (which features matter most across all predictions).

## Deep-Dive Explanation

**Bias and feedback loops, formally.** Aggregation bias occurs when a single model is fit across
subgroups that actually have a different relationship between features and outcome, so the fitted
model is a compromise that fits no subgroup well. A feedback loop is what happens when a model's
own outputs change the data used to train its next version: a policing model that directs more
patrols to a neighborhood generates more recorded arrests there, not necessarily more actual crime,
and if those arrest records are then used as a proxy label for "crime rate" in the next training
run, the model's own prior decisions are laundered into ground truth. The same structure appears
whenever a deployed model's decisions influence which outcomes get observed and fed back into
future training data, quietly compounding an initial bias each cycle rather than merely repeating
it.

**Fairness, formally.** Let Ŷ be the model's prediction, Y the true outcome, and A a protected
group attribute. Demographic parity requires P(Ŷ=1 | A=a) to be equal across all groups a.
Equalized odds requires P(Ŷ=1 | Y=y, A=a) to be equal across groups for both y=0 and y=1, that is,
equal true positive rates and equal false positive rates across groups, using the same confusion
matrix machinery as chapter 1.6 but computed separately per group. Predictive parity requires
P(Y=1 | Ŷ=1, A=a) to be equal across groups: among people who received the same prediction, the
actual outcome rate should match. Kleinberg, Mullainathan, and Raghavan proved that when the base
rate P(Y=1 | A=a) genuinely differs between groups, no classifier other than a perfect one can
simultaneously satisfy equalized odds and predictive parity (Kleinberg, Mullainathan, and Raghavan,
[*Inherent Trade-Offs in the Fair Determination of Risk Scores*](https://arxiv.org/abs/1609.05807),
ITCS, 2017). Chouldechova proved a closely related impossibility result specifically for binary risk
scores, showing that unequal false positive and false negative rates across groups follow
mathematically from unequal base rates whenever predictive parity holds (Chouldechova,
[*Fair Prediction with Disparate Impact: A Study of Bias in Recidivism Prediction Instruments*](https://doi.org/10.1089/big.2016.0047),
*Big Data*, 2017). This is not a modeling failure to be engineered away; it is a mathematical
consequence of the group base rates differing, which is precisely why choosing a fairness definition
is a decision about which error to tolerate, not a bug to fix.

**Explainability, formally.** LIME (Local Interpretable Model-agnostic Explanations) explains one
prediction by sampling points near the input, observing how the black-box model's output changes,
and fitting a simple, interpretable model, typically a sparse linear model, to that local
neighborhood; the surrogate model's coefficients become the explanation for that single prediction
(Ribeiro, Singh, and Guestrin,
[*"Why Should I Trust You?": Explaining the Predictions of Any Classifier*](https://dl.acm.org/doi/10.1145/2939672.2939778),
KDD, 2016). SHAP (SHapley Additive exPlanations) instead adapts the Shapley value from cooperative
game theory: it treats each feature as a "player" contributing to the difference between a
prediction and a baseline average prediction, and distributes that difference across features in
the unique way that satisfies a specific set of consistency properties (a feature that contributes
nothing gets zero credit, and contributions add up exactly to the total difference from baseline)
(Lundberg and Lee,
[*A Unified Approach to Interpreting Model Predictions*](https://proceedings.neurips.cc/paper/2017/file/8a20a8621978632d76c43dfd28b67767-Paper.pdf),
NeurIPS, 2017). Both methods are model-agnostic, working on any black-box classifier or regressor,
and both produce local, per-prediction explanations, though SHAP values can also be aggregated
across many predictions to produce a global feature-importance summary. A well-documented real-world
case of aggregation and measurement bias combined is a widely used healthcare risk-prediction
algorithm that used a patient's predicted future healthcare *cost* as a proxy for healthcare *need*;
because less money was historically spent on Black patients with the same level of underlying
illness, the algorithm systematically assigned Black patients lower risk scores than white patients
at the same actual level of need, reducing referrals to a care-management program that used the
score as its gate (Obermeyer, Powers, Vogeli, and Mullainathan,
[*Dissecting Racial Bias in an Algorithm Used to Manage the Health of Populations*](https://www.science.org/doi/10.1126/science.aax2342),
*Science*, 2019).
