## TL;DR

The last two chapters covered giving a model new behavior and new knowledge. This chapter covers making
a model smaller and cheaper to run, without giving up much of either. Three techniques do most of the
work, and they attack different parts of the problem. Distillation trains a small model to reproduce a
large one's behavior: Hinton et al. built on Caruana et al.'s earlier demonstration that it was
possible to "compress the knowledge in an ensemble into a single model which is much easier to deploy,"
developing that idea further with their own distillation technique, and a concrete case study,
DistilBERT, showed what that can look like in practice, a model built to "reduce the size of a BERT
model by 40%, while retaining 97% of its language understanding capabilities and being 60% faster."
Quantization leaves the model's architecture untouched and instead represents its weights with fewer
bits: GPTQ reported it "can quantize GPT models with 175 billion parameters in approximately four GPU
hours, reducing the bitwidth down to 3 or 4 bits per weight, with negligible accuracy degradation," a
reduction dramatic enough that it can "execute an 175 billion-parameter model inside a single GPU for
generative inference." Pruning removes weights outright: SparseGPT showed that "large-scale generative
pretrained transformer (GPT) family models can be pruned to at least 50% sparsity in one-shot, without
any retraining, at minimal loss of accuracy." None of these three techniques compete with the others;
production systems commonly stack all three, distilling a large model down, quantizing the result, and
pruning what is left.

## High-Level Explanation

Each of these three techniques shrinks a model along a different axis, and it helps to picture what
literally changes in each case. Distillation changes the model itself: a smaller student network,
usually with fewer layers or a narrower hidden dimension, is trained to match a larger teacher network's
behavior rather than trained from scratch on raw labels alone. It happens during training, and it
produces a genuinely different, smaller architecture. Quantization changes only how each weight is
stored: instead of a 32-bit or 16-bit floating-point number, a weight is represented with 8, 4, or even
fewer bits, shrinking memory and often speeding up computation, without touching the number of weights
or the model's architecture at all. It is typically applied after training is complete, sometimes in
minutes to hours rather than a full training run. Pruning changes how many weights exist: individual
weights, or entire structured blocks of them, are removed because they contribute little to the model's
output, leaving a sparser network that needs less computation and less memory to run. Because these
three techniques touch different things, architecture, numeric representation, and weight count, they
compose: a distilled model can be quantized, and a quantized model can be pruned, each pass compounding
the savings of the one before it.

## Deep-Dive Explanation

**Distillation trains a smaller model on a larger one's outputs, not just on the original labels, and
the idea is older than the current wave of large language models.** Hinton et al. opened with the
motivating problem: "a very simple way to improve the performance of almost any machine learning
algorithm is to train many different models on the same data and then to average their predictions," but
"making predictions using a whole ensemble of models is cumbersome and may be too computationally
expensive to allow deployment to a large number of users, especially if the individual models are large
neural nets." Caruana and collaborators had already shown it was possible to "compress the knowledge in
an ensemble into a single model which is much easier to deploy," and Hinton et al. developed that
approach further with their own distillation technique, training a small student model on the large
teacher's softened output probabilities
rather than on raw hard labels alone, since those probabilities carry information about which wrong
answers the teacher considered plausible, not just which answer was correct. The paper reported
"surprising results on MNIST" and a real production win, improving "the acoustic model of a heavily used
commercial system by distilling the knowledge in an ensemble of models into a single model." DistilBERT
is the concrete case that made this approach mainstream for transformer language models: distilled during
pretraining itself rather than only at the fine-tuning stage, it managed to "reduce the size of a BERT
model by 40%, while retaining 97% of its language understanding capabilities and being 60% faster,"
figures specific enough to make the tradeoff plain, a meaningful chunk of size and latency traded for a
small, bounded amount of capability.

**Quantization leaves the number of weights and the architecture untouched and instead shrinks how much
storage each weight consumes, and modern post-training methods can do this to a full-scale model in
hours rather than requiring a training run.** GPTQ is a representative case: it "can quantize GPT models
with 175 billion parameters in approximately four GPU hours, reducing the bitwidth down to 3 or 4 bits
per weight, with negligible accuracy degradation." The practical payoff is not just a smaller file on
disk. Lower-bit weights mean less data to move during inference, and GPTQ reported "end-to-end inference
speedups over FP16, of around 3.25x when using high-end GPUs (NVIDIA A100) and 4.5x when using more
cost-effective ones (NVIDIA A6000)." Taken to its conclusion, the compression can change what hardware a
model needs at all: GPTQ's quantization was precise enough to "execute an 175 billion-parameter model
inside a single GPU for generative inference," a model that would otherwise need to be split across
several. Because quantization does not change the architecture or retrain the model, it is usually the
cheapest of the three techniques to apply, and it is common to see it layered on top of a model that has
already been distilled or pruned.

**Pruning removes weights outright rather than shrinking how they are stored, and recent work showed
this can be done to language models at scale without the retraining pruning has traditionally required.**
SparseGPT's headline result: "large-scale generative pretrained transformer (GPT) family models can be
pruned to at least 50% sparsity in one-shot, without any retraining, at minimal loss of accuracy." On the
largest models tested, OPT-175B and BLOOM-176B, the method reached "60% unstructured sparsity with
negligible increase in perplexity," meaning more than half the weights in those models could be zeroed
out and ignored at inference time with only a small quality cost. The method is not limited to
unstructured sparsity either: it "generalizes to semi-structured (2:4 and 4:8) patterns, and is
compatible with weight quantization approaches," meaning the sparsity pattern can be shaped to match what
specific inference hardware actually accelerates, and pruning and quantization can be applied to the same
model together rather than as competing choices.

## Hands-On: Quantize a Model to INT8 and Check What It Costs

The clearest way to see quantization's tradeoff is to run it: shrink a model's weights to 8-bit integers,
measure how much smaller it gets, and check whether it still answers the same way it did before.

**Step 1: Load a model built from real `nn.Linear` layers.** DistilBERT, not a GPT-2-style model, is
used deliberately here: GPT-2's attention and feed-forward projections use a different internal layer
type (`Conv1D`) that PyTorch's dynamic quantization does not target, so quantizing a GPT-2-style model
this way would silently compress almost nothing. DistilBERT's layers are ordinary `nn.Linear`, so dynamic
quantization applies broadly across the model.

```python
import io
import torch
from transformers import AutoModelForMaskedLM, AutoTokenizer

model_name = "distilbert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
fp32_model = AutoModelForMaskedLM.from_pretrained(model_name)
fp32_model.eval()

def model_size_mb(model):
    buffer = io.BytesIO()
    torch.save(model.state_dict(), buffer)
    return buffer.tell() / (1024 ** 2)

fp32_size = model_size_mb(fp32_model)
print(f"fp32 model size: {fp32_size:.1f} MB")
```

**Step 2: Apply dynamic quantization to every `nn.Linear` layer and measure the new size.** This is a
CPU-oriented, weights-only quantization technique built into PyTorch, simpler than the calibration-based,
GPU-focused approach GPTQ uses, but it demonstrates the same underlying idea: fewer bits per weight, same
architecture.

```python
quantized_model = torch.quantization.quantize_dynamic(
    fp32_model, {torch.nn.Linear}, dtype=torch.qint8
)
quantized_model.eval()

quantized_size = model_size_mb(quantized_model)
print(f"int8 model size: {quantized_size:.1f} MB")
print(f"size reduction: {(1 - quantized_size / fp32_size) * 100:.1f}%")
```

**Step 3: Check whether the quantized model still predicts the same words.** A masked-language-modeling
task, predicting the word hidden behind `[MASK]`, gives a simple before-and-after comparison: if
quantization preserved the model's behavior, the top prediction should usually match.

```python
test_sentences = [
    "The capital of France is [MASK].",
    "Water is made of hydrogen and [MASK].",
    "The opposite of hot is [MASK].",
]

def top1_predictions(model, tokenizer, sentences):
    predictions = []
    with torch.no_grad():
        for sentence in sentences:
            inputs = tokenizer(sentence, return_tensors="pt")
            mask_index = (inputs.input_ids == tokenizer.mask_token_id).nonzero(as_tuple=True)[1]
            logits = model(**inputs).logits
            top_token_id = logits[0, mask_index, :].argmax(dim=-1)
            predictions.append(tokenizer.decode(top_token_id))
    return predictions

fp32_predictions = top1_predictions(fp32_model, tokenizer, test_sentences)
quantized_predictions = top1_predictions(quantized_model, tokenizer, test_sentences)

for sentence, fp32_pred, q_pred in zip(test_sentences, fp32_predictions, quantized_predictions):
    match = "same" if fp32_pred.strip() == q_pred.strip() else "different"
    print(f"{sentence}\n  fp32: {fp32_pred!r}  int8: {q_pred!r}  ({match})")
```

**Step 4: Read the tradeoff.** The size printed in Step 2 typically drops substantially, since the
linear layers that dominate a transformer's parameter count now store 8-bit integers instead of 32-bit
floats, while Step 3's predictions typically agree across most or all of the test sentences, exactly the
shape of tradeoff GPTQ reported at a much larger scale: meaningfully smaller, at a small and bounded cost
to behavior.

None of these stages require all three techniques to run. A team can distill only, quantize only, prune
only, or chain any combination, and the order matters less than making sure each stage's savings are
measured against the model it actually started from, not against the original, uncompressed teacher.
