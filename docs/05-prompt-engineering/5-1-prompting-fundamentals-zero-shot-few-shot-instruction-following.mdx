## TL;DR

Prompting is how a task is communicated to an LLM without updating any of its weights. In **zero-shot**
prompting, the prompt contains only a natural-language task description; in **few-shot** prompting, it
also includes a handful of worked input-output examples, letting the model infer the task's format
from demonstrations rather than instructions alone (Brown et al., in-context learning, no gradient
updates in either case). **Instruction tuning** (FLAN, Wei et al., 2021) fine-tunes a model on many
tasks phrased as instructions, teaching it to generalize to new, unseen instructions in a zero-shot
setting rather than needing examples to infer the expected format. A further step, reinforcement
learning from human feedback (InstructGPT, Ouyang et al., 2022, previewed here and covered fully in
Phase 7), trains a model specifically to follow a user's actual intent, closing the gap between a raw
pretrained base model, which treats a prompt as a text-continuation problem, and a model that reliably
obeys a plain instruction. Even with a capable, instruction-tuned model, few-shot prompts remain
sensitive to how they are built: example order (Lu et al., 2021) and systematic biases toward
majority, recent, or common labels (Zhao et al., 2021) can swing accuracy substantially, and
semantically similar example selection (Liu et al., 2021) outperforms random choice.

## High-Level Explanation

Think of onboarding two different new hires for the same task. One hire has no general training and
needs to see several completed examples of the specific task, in the specific format expected, before
producing correct work themselves, the equivalent of few-shot prompting: showing worked examples so the
model can infer the expected pattern. A second hire has been broadly trained to follow written
instructions across many kinds of tasks, and can often do this new task correctly from a plain
instruction alone, no examples needed, the equivalent of an instruction-tuned model responding well to
a zero-shot prompt. But even the well-trained second hire's output can shift noticeably depending on
which examples happen to be shown first, in what order, or how similar those examples are to the actual
task at hand, which is exactly the sensitivity few-shot prompts exhibit even with a capable model
underneath them.

## Deep-Dive Explanation

**Defining zero-shot, one-shot, and few-shot precisely.** Brown et al.
([*Language Models are Few-Shot Learners*](https://arxiv.org/abs/2005.14165), 2020) define these
three settings purely by how many worked examples appear in the prompt alongside a natural-language
task description: zero for zero-shot, one for one-shot, and a handful, typically ten to a hundred or so,
for few-shot. Critically, no gradient updates or weight changes happen in any of the three settings;
the model's parameters are entirely fixed, and everything the model has to work with is contained in
the prompt itself, sometimes called in-context learning. This is a fundamentally different mechanism
from fine-tuning, which does update weights on a task-specific dataset ahead of time.

**Instruction tuning: teaching a model to generalize across instructions, not just examples.** Wei et
al. ([*Finetuned Language Models Are Zero-Shot Learners*](https://arxiv.org/abs/2109.01652), FLAN,
2021) fine-tune a language model on a large mixture of tasks, each phrased as a natural-language
instruction, and show this substantially improves zero-shot performance specifically on held-out task
types the model was never instruction-tuned on. The mechanism is generalization across instruction
phrasing and task structure, not memorization of any single task's format: a model instruction-tuned
this way can often follow a new instruction it has never seen phrased that way before, closing much of
the gap between zero-shot and few-shot performance that a purely pretrained model exhibits.

**RLHF: training a model to follow actual user intent.** InstructGPT (Ouyang et al.,
[*Training Language Models to Follow Instructions with Human Feedback*](https://arxiv.org/abs/2203.02155),
2022, previewed here and covered fully in Phase 7) goes a step further than FLAN's multitask
instruction fine-tuning. The pipeline first fine-tunes a model on human-written demonstrations of
desired behavior, then trains a separate reward model on human rankings of multiple candidate outputs,
then uses that reward model to further fine-tune the original model via reinforcement learning. The
paper's headline result, that human evaluators preferred outputs from a 1.3-billion-parameter
InstructGPT model over the far larger 175-billion-parameter base GPT-3 model, demonstrates that this
alignment pipeline, not raw scale, is what drives reliable instruction-following. This is a distinct
mechanism from FLAN: FLAN uses only supervised instruction data across many tasks, with no human
preference model or reinforcement learning step involved.

**Why a base model and an instruction-tuned model respond so differently to the same prompt.** A base
model, one that has only been pretrained on next-token prediction and not further tuned as described
above, is fundamentally a text-continuation engine: given a prompt that looks like an instruction, it
may continue the text in an unexpected way, such as generating more instructions rather than following
the one given, since nothing in its training specifically taught it that a prompt shaped like an
instruction should be obeyed. An instruction-tuned model, having been trained through a process like
FLAN's or InstructGPT's, is expected to treat the prompt as something to act on rather than merely
continue, which is precisely why zero-shot prompting becomes far more reliable once instruction tuning
has happened, and why a base model more often needs few-shot examples to demonstrate the expected
input-output pattern instead.

**Few-shot prompts remain sensitive to example order.** Even with a capable model, Lu et al.
([*Fantastically Ordered Prompts and Where to Find Them*](https://arxiv.org/abs/2104.08786), 2021)
show that simply permuting the order of the same few-shot examples, with none added, removed, or
reworded, can swing accuracy on the same task from near state-of-the-art to close to random chance.
This means the specific sequence in which examples are presented is not a cosmetic detail; it is a
variable that measurably affects output quality on its own.

**Few-shot prompts carry systematic biases that calibration can correct.** Zhao et al.
([*Calibrate Before Use: Improving Few-Shot Performance of Language Models*](https://arxiv.org/abs/2102.09690),
2021) identify three specific biases in few-shot prompted models: majority-label bias, favoring
whichever label appeared most often among the shown examples; recency bias, favoring the label of
whichever example was shown last; and common-token bias, favoring tokens that are simply more frequent
in the model's pretraining data, regardless of the actual task. Their proposed fix, contextual
calibration, probes the model with a content-free input, such as the literal string "N/A," to estimate
this bias directly and then adjusts the output distribution to cancel it out, which both raises average
accuracy and reduces the variance introduced by different example choices or orderings.

**Choosing which examples to show matters as much as how many.** Liu et al.
([*What Makes Good In-Context Examples for GPT-3?*](https://arxiv.org/abs/2101.06804), 2021) find that
selecting few-shot examples that are semantically similar to the specific test input, for instance via
nearest-neighbor retrieval in an embedding space, substantially and consistently outperforms randomly
chosen few-shot examples across a range of task types. This means the same fixed pool of candidate
examples can produce meaningfully different results depending purely on which ones are selected for a
given input, independent of prompt wording.

**Putting prompting fundamentals together.** Whether zero-shot prompting is reliable at all depends
heavily on whether the model in hand has been instruction-tuned; a base model more often needs few-shot
demonstrations to behave predictably. Once few-shot prompting is in play, three additional variables,
example order, example selection, and susceptibility to majority/recency/common-token bias, can each
independently swing accuracy as much as the underlying task's difficulty does. Treating prompt
construction as a deliberate design decision, not an afterthought, is the foundation the next chapter
builds on with more advanced reasoning-elicitation patterns.
