## TL;DR

Training a large network from scratch, an AlexNet-scale CNN (2.3) or a Transformer (2.5), needs
huge labeled datasets and enormous compute. **Transfer learning** avoids repeating that cost by
starting from a model already trained on a large source task and adapting it to a new target task,
rather than starting from randomly initialized weights. Two main strategies exist: **feature
extraction** freezes the pretrained weights and trains only a new final layer on the target data,
while **fine-tuning** continues training some or all of the pretrained weights on the target task,
usually with a smaller learning rate so the model adjusts without destroying what it already
learned. Naively continuing to train on a new task risks **catastrophic forgetting**, where
performance on the original task degrades as the new task overwrites earlier learning. This same
pattern, pretrain on a large, general dataset, then adapt to a smaller, specific one, is the
paradigm behind both modern computer vision, where ImageNet-pretrained backbones are standard
starting points, and modern language models, where BERT and GPT-style models are pretrained on
massive unlabeled text and then adapted to downstream tasks.

## High-Level Explanation

A CNN's layers form a hierarchy (2.3): early layers detect generic patterns like edges and
textures, and later layers combine those into increasingly task-specific features. The generic,
early-layer patterns turn out to be useful across a wide range of visual tasks, not just the one
the network was originally trained on: an edge detector learned from classifying everyday photos
is still a useful edge detector for classifying medical images or satellite photos. Transfer
learning exploits this by reusing a network's early, general-purpose representations instead of
relearning them from a small target dataset, and only adapting the later, more task-specific parts
of the network. The benefit is largest exactly when it matters most: when the target dataset is too
small to train a large network from scratch without overfitting.

There are two common ways to adapt a pretrained network. In **feature extraction**, every
pretrained weight is frozen (held fixed, receiving no gradient updates), a new final layer suited
to the target task is added on top, and only that new layer is trained. In **fine-tuning**, some or
all of the pretrained weights are unfrozen and continue to be updated by backpropagation (2.2) on
the target data, typically with a much smaller learning rate than the original training used, so
the already-useful weights shift gradually rather than being overwritten by large, disruptive
updates.

## Deep-Dive Explanation

**Formalizing the transfer.** A source domain and task (D_s, T_s), typically a large, general
dataset like ImageNet for vision or a large unlabeled text corpus for language, is used to train a
model. A target domain and task (D_t, T_t), typically smaller and more specific, is what the model
actually needs to perform well on. Transfer learning uses the parameters learned from (D_s, T_s) as
the starting point for learning (D_t, T_t), rather than initializing weights randomly (2.1) and
training on D_t alone.

**How transferable are features, layer by layer.** A systematic study measured how much accuracy a
network loses when its first n layers are copied from a source-task network and frozen (or
fine-tuned), and the remaining layers are trained fresh on a target task. Two consistent findings
emerged: transferability decreases as n increases, since later layers are more specific to the
source task, and it also decreases as the source and target tasks become less related. The same
study found that starting from pretrained weights and fine-tuning on the target task outperformed
training from scratch on the target task even when enough target data was available to train from
scratch, because pretrained weights are also a better optimization starting point, not just a
source of extra effective data (Yosinski, Clune, Bengio, and Lipson,
[*How Transferable Are Features in Deep Neural Networks?*](https://arxiv.org/abs/1411.1792), NIPS,
2014).

**Catastrophic forgetting.** When a network continues training on a new task, gradient descent
(2.2) has no built-in mechanism to preserve what was useful for the old task; weights that mattered
for the source task can be overwritten by updates that only help the target task, causing source-task
performance to collapse even if it is never evaluated again during adaptation. This is a direct
consequence of how gradient descent works: it moves weights in whatever direction reduces the
current loss, with no awareness of a previous task unless something explicitly accounts for it.
One mitigation adds a penalty term that slows down updates to weights identified as important for
the earlier task, based on the estimated sensitivity of that task's performance to each weight
(Kirkpatrick, Pascanu, Rabinowitz, Veness, Desjardins, Rusu, Milan, Quan, Ramalho, Grabska-Barwinska,
Hassabis, Clopath, Kumaran, and Hadsell,
[*Overcoming Catastrophic Forgetting in Neural Networks*](https://www.pnas.org/doi/10.1073/pnas.1611835114),
PNAS, 2017). In practice, using a small fine-tuning learning rate and unfreezing only the later
layers are simpler, more commonly used ways to limit how much a pretrained model's useful earlier
representations get disturbed.

**Domain adaptation versus task adaptation.** It is useful to separate two different kinds of
mismatch between source and target. Domain adaptation covers the same task but a different data
distribution, for example a classifier trained on daytime photos applied to nighttime photos.
Task adaptation covers the same general domain but a different task, for example a backbone
trained for image classification adapted to object detection. Real transfer learning problems
often involve both at once, and the degree of mismatch on either axis is what drives how much
fine-tuning, versus pure feature extraction, is needed.

**The pretrain-then-adapt paradigm at scale.** The same freeze-or-fine-tune logic scaled up is the
foundation of modern language models. BERT is pretrained on a large unlabeled text corpus using a
masked-language-modeling objective (predicting words that have been randomly hidden from the
input), producing general-purpose language representations, and is then fine-tuned on much smaller,
labeled datasets for specific downstream tasks (Devlin, Chang, Lee, and Toutanova,
[*BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding*](https://aclanthology.org/N19-1423/),
NAACL, 2019). GPT instead pretrains with an autoregressive, next-token-prediction objective on a
large text corpus and is then adapted to downstream tasks (Radford, Narasimhan, Salimans, and
Sutskever,
[*Improving Language Understanding by Generative Pre-Training*](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf),
OpenAI, 2018). Both are instances of the same pattern this chapter describes: pretrain once on a
large, general dataset, then adapt cheaply per target task. Exactly how large language models are
pretrained and how they are adapted (fine-tuning, and prompting-based adaptation that needs no
weight updates at all) is covered in depth in later phases of this curriculum; this chapter
establishes the general transfer learning principle those approaches build on.

```python
# Illustrative only: which layers to freeze depends on target-task similarity
# and target dataset size, not on framework-specific syntax (2.7 covers frameworks).

def configure_transfer(layers, strategy, unfreeze_from_layer=None):
    """layers: list of layer names from earliest to latest.
    strategy: 'feature_extraction' or 'fine_tune'.
    unfreeze_from_layer: for fine_tune, the earliest layer index to unfreeze;
    later layers are more task-specific, so fine-tuning tends to start there."""
    trainable = {}
    for i, name in enumerate(layers):
        if strategy == 'feature_extraction':
            trainable[name] = False          # every pretrained layer stays frozen
        elif strategy == 'fine_tune':
            trainable[name] = i >= unfreeze_from_layer   # unfreeze later layers only
    return trainable   # a new task-specific output layer is always trainable, added separately
```
