## TL;DR

Every network described so far in this phase, from a two-layer MLP (2.1) to a full Transformer
(2.5), needs to actually be implemented, trained on real hardware, and have its gradients computed
correctly for backpropagation (2.2) to work. A **deep learning framework** provides three things
that make this practical: **automatic differentiation** (computing exact gradients of arbitrary
differentiable code without hand-deriving them), GPU-accelerated tensor operations, and pre-built
layers and optimizers. The three dominant frameworks take different design approaches. **PyTorch**
runs eagerly, executing operations immediately in ordinary Python, which makes it easy to debug and
has made it the default in research. **TensorFlow** now also runs eagerly by default but retains
strong tooling for compiling models into optimized graphs and deploying them to servers, mobile,
and browsers. **JAX** takes a functional approach, offering composable transformations, most
notably automatic differentiation and just-in-time compilation, that can be combined in ways the
other two do not support as directly. All three exist to do the same underlying job: mechanize the
chain rule so nobody has to re-derive backpropagation by hand for every new architecture.

## High-Level Explanation

Chapter 2.2 derived backpropagation by hand for a small MLP: computing each weight's gradient by
applying the chain rule layer by layer, backward from the loss. A real network, especially one as
large as a modern CNN (2.3) or Transformer (2.5), makes this manual approach impractical. **Automatic
differentiation** (autodiff) solves this generically: as the framework runs the forward pass, it
records every operation performed on the input tensors, building up a record of exactly how the
output depends on each input. Running that record backward, applying the chain rule at each
recorded step, computes the gradient of the loss with respect to every parameter automatically, no
matter how deep or unusual the network's structure is. This is not an approximation of
backpropagation, it is a direct, mechanized implementation of the same chain rule from chapter 2.2,
generalized to arbitrary differentiable code rather than a fixed sequence of layers.

Every framework built on autodiff supports roughly the same training loop: define a model as a
collection of parameters and operations, run a forward pass to get a prediction, compute a loss,
run a backward pass (autodiff computes every gradient), and take an optimizer step (2.2's gradient
descent, momentum, or Adam) to update the parameters. What differs between PyTorch, TensorFlow, and
JAX is how directly Python code maps onto this loop, and how much of it can be compiled and
optimized before it runs.

## Deep-Dive Explanation

**Reverse-mode automatic differentiation, formally.** As the forward pass executes, the framework
builds a computation graph (dynamically, operation by operation, in PyTorch and JAX's tracing;
statically compiled ahead of time when using TensorFlow's @tf.function or classic graph mode) where
each node is an operation and each edge carries a tensor. Every operation also registers its local
derivative rule (for example, the local derivative of a multiplication node with respect to each of
its two inputs). Reverse-mode autodiff then walks this graph backward from the loss, at each node
computing a vector-Jacobian product, the chain rule step that combines the gradient flowing in from
later in the graph with that node's local derivative, and accumulates the result at every parameter
that fed into the computation. This is exactly the layer-by-layer backward pass chapter 2.2 walked
through by hand, generalized to any graph shape, not only a stack of dense layers.

**PyTorch** builds its computation graph dynamically: each time the forward pass runs, PyTorch's
autograd engine records the actual sequence of tensor operations Python executed, including any
data-dependent control flow (an `if` statement or a `for` loop whose length depends on the input,
useful for variable-length sequences like 2.4's RNNs). Calling `.backward()` on the final loss
tensor walks that freshly recorded graph backward. Because the graph is rebuilt every forward pass
using ordinary Python execution, standard debugging tools and print statements work as expected,
which is a major reason PyTorch became the default choice in research (Paszke, Gross, Massa, Lerer,
Bradbury, Chanan, Killeen, Lin, Gimelshein, Antiga, Desmaison, Kopf, Yang, DeVito, Raison, Tejani,
Chilamkurthy, Steiner, Fang, Bai, and Chintala,
[*PyTorch: An Imperative Style, High-Performance Deep Learning Library*](https://arxiv.org/abs/1912.01703),
NeurIPS, 2019).

**TensorFlow** originally required defining a static computation graph up front and running it
inside a separate session, a design that enabled aggressive optimization and easy deployment but
made debugging harder, since the code that built the graph did not execute the same way as ordinary
Python. TensorFlow 2 changed the default to eager execution, matching PyTorch's immediate-execution
style, while keeping the option to trace a Python function into an optimized, compiled graph with
the `@tf.function` decorator when performance matters more than step-by-step debuggability.
TensorFlow's deployment ecosystem, TensorFlow Serving for server inference, TensorFlow Lite for
mobile and embedded devices, and TensorFlow.js for browsers, remains a distinguishing strength built
up over its graph-based history (Abadi, Barham, Chen, Chen, Davis, Dean, Devin, Ghemawat, Irving,
Isard, Kudlur, Levenberg, Monga, Moore, Murray, Steiner, Tucker, Vasudevan, Warden, Wicke, Yu, and
Zheng,
[*TensorFlow: A System for Large-Scale Machine Learning*](https://www.usenix.org/conference/osdi16/technical-sessions/presentation/abadi),
OSDI, 2016).

**JAX** takes a functional programming approach: functions are pure (no hidden internal state; the
same inputs always produce the same outputs) and arrays are immutable. On top of this, JAX exposes
a small set of composable function transformations that can be layered on top of each other: `grad`
computes the gradient of a function, `jit` compiles a function ahead of time using XLA (a
linear-algebra compiler shared with TensorFlow) for substantial speedups, `vmap` automatically
rewrites a function written for a single example into one that runs efficiently on a batch, and
`pmap` distributes a computation across multiple devices. Because these transformations compose
(`jit(grad(loss_fn))` compiles the gradient computation itself, for example), JAX is popular for
research that needs custom training procedures beyond a standard forward-loss-backward-step loop
(Frostig, Johnson, and Leary,
[*Compiling Machine Learning Programs via High-Level Tracing*](https://cs.stanford.edu/~rfrostig/pubs/jax-mlsys2018.pdf),
SysML, 2018). Unlike PyTorch and TensorFlow, JAX itself has no built-in notion of a layer or a
model object; libraries built on top of JAX (such as Flax) add that structure.

**Eager versus graph execution, practically.** Eager execution (PyTorch's default, and TensorFlow
2's default) runs each operation immediately as ordinary Python, which makes debugging as simple as
using a debugger or print statements, at some cost to raw execution speed since the framework
cannot see the whole computation ahead of time to optimize it. Graph or compiled execution (classic
TensorFlow, `@tf.function`, and JAX's `jit`) instead traces or compiles the computation before
running it, allowing operations to be fused and scheduled efficiently, at the cost of a compilation
step and a debugging experience one step removed from ordinary Python. Most production training
pipelines in every framework end up compiling the hot training loop once debugging is done, using
eager or interpreted execution mainly during development.

```python
# Illustrative PyTorch: the same chain-rule computation chapter 2.2 derived by hand,
# now computed automatically by calling .backward() instead of deriving each gradient.
import torch

x = torch.tensor([1.0, 2.0], requires_grad=False)
w = torch.tensor([0.5, -0.3], requires_grad=True)   # a parameter autodiff will track
b = torch.tensor(0.1, requires_grad=True)

y_pred = torch.tanh((x * w).sum() + b)   # forward pass: same activation as chapter 2.1
target = torch.tensor(1.0)
loss = (y_pred - target) ** 2            # forward pass continues: squared error loss

loss.backward()   # autodiff walks the recorded graph backward, applying the chain rule
print(w.grad, b.grad)   # gradients autodiff computed, with no manual chain-rule derivation
```
