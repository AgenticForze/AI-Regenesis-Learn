## TL;DR

Chapter 2.1 covered the forward pass: features go in, a prediction comes out. Backpropagation is
how a network learns from being wrong. It runs the chain rule backward through the network,
starting at the loss and working toward the input layer, to compute exactly how much each
individual weight contributed to the error. Gradient descent then nudges every weight in the
direction that reduces that error. Plain gradient descent is slow and easily gets stuck, so in
practice almost nobody uses it unmodified: momentum smooths the update direction using recent
history, and Adam, the most widely used optimizer in deep learning today, adapts the step size
separately for every single parameter.

## High-Level Explanation

The forward pass (2.1) computes a prediction, and a **loss function** compares that prediction to
the true label with a single number: how wrong was the network. **Backpropagation** answers the
next question: for each individual weight in the network, if I nudged it slightly, would the loss
go up or down, and by how much? It answers this efficiently by starting at the loss and working
backward, layer by layer, reusing the arithmetic from the forward pass rather than recomputing
everything from scratch for every single weight. The name comes directly from this direction: error
information propagates backward, from the output layer toward the input layer, which is the
opposite direction the forward pass ran in.

Once every weight has a gradient (a number saying "increasing this weight increases the loss by
this much"), an **optimizer** decides how to actually update the weights. The simplest choice,
gradient descent, moves every weight a small step in the direction that reduces the loss, and
repeats this thousands or millions of times. In practice, plain gradient descent converges slowly
and can get stuck in flat regions or oscillate in narrow valleys of the loss surface, which is why
virtually every production training run instead uses a variant that adds memory of past updates
(momentum) or adapts the step size per parameter (Adam and its relatives).

## Deep-Dive Explanation

**The chain rule, applied layer by layer.** For a single weight w feeding into a unit with
pre-activation z, activation a = φ(z), and eventual loss L, the chain rule gives
∂L/∂w = (∂L/∂a) · (∂a/∂z) · (∂z/∂w). The key efficiency trick is that ∂L/∂a for a hidden unit is
itself built from the gradients already computed for every unit in the next layer that this unit
feeds into, so the algorithm computes each layer's gradients once, moving backward, and reuses them
rather than re-deriving the chain rule from the loss all the way down for every single weight
independently. Rumelhart, Hinton, and Williams popularized this technique for training multilayer
networks and showed it could discover useful internal hidden-layer representations without those
representations being hand-specified (Rumelhart, Hinton, and Williams,
[*Learning Representations by Back-Propagating Errors*](https://www.nature.com/articles/323533a0),
*Nature*, 1986). Modern frameworks (PyTorch, TensorFlow, JAX, covered in 2.7) implement this
automatically as reverse-mode automatic differentiation: every operation in the forward pass is
recorded, and the framework walks that record backward to compute every gradient, so a practitioner
essentially never derives ∂L/∂w by hand for a real model.

**Vanishing and exploding gradients.** Because the chain rule multiplies terms together across
every layer, a deep network's earliest-layer gradients are a product of many factors, one per
layer. If those factors are consistently smaller than 1 (as sigmoid and tanh's gradients are away
from z=0), the product shrinks toward zero as depth increases, so early layers receive a gradient
too small to learn from at any reasonable learning rate, the vanishing gradient problem. If the
factors are consistently larger than 1, the product grows unboundedly instead, causing unstable,
divergent updates, the exploding gradient problem. Bengio, Simard, and Frasconi formally analyzed
why gradient-based training struggles to learn dependencies that span many steps for exactly this
reason (Bengio, Simard, and Frasconi,
[*Learning Long-Term Dependencies with Gradient Descent Is Difficult*](https://dl.acm.org/doi/10.1109/72.279181),
*IEEE Transactions on Neural Networks*, 1994). This is precisely why chapter 2.1's activation
choice matters at training time, not just at inference: ReLU's gradient is exactly 1 for any
positive input, so it does not contribute a shrinking factor the way sigmoid and tanh do, and why
weight initialization scale matters (2.1): He initialization scales a layer's initial weights by
√(2/fan_in) specifically to keep activation variance roughly stable through a deep ReLU network
(He, Zhang, Ren, and Sun,
[*Delving Deep into Rectifiers*](https://openaccess.thecvf.com/content_iccv_2015/papers/He_Delving_Deep_into_ICCV_2015_paper.pdf),
ICCV, 2015), extending the earlier Glorot/Xavier scheme derived for sigmoid and tanh networks
(Glorot and Bengio,
[*Understanding the Difficulty of Training Deep Feedforward Neural Networks*](https://proceedings.mlr.press/v9/glorot10a.html),
AISTATS, 2010). Exploding gradients are commonly handled directly at training time with gradient
clipping: capping the gradient's norm before applying the update, regardless of what caused the
spike.

**From gradient to update: gradient descent variants.** Batch gradient descent computes the
gradient over the entire training set before taking one step, which is accurate but slow and
memory-heavy for large datasets. Stochastic gradient descent (SGD) takes a step after every single
example, which is fast per step but noisy. Mini-batch gradient descent, the practical default,
computes the gradient over a small batch (commonly 32 to 512 examples) as a compromise between the
two. **Momentum** keeps a running exponentially-weighted average of past gradients, v, and updates
weights using that average rather than the raw current gradient: v ← β·v − η·∇L(θ), θ ← θ + v,
where β (typically around 0.9) controls how much past gradients still influence the current step.
This smooths out noisy per-batch gradients and accelerates movement through consistently
downhill directions, the same technique Rumelhart, Hinton, and Williams included in their original
1986 backpropagation formulation.

**Adam** (Adaptive Moment Estimation) combines momentum with a second idea: giving every individual
parameter its own effective learning rate, scaled down for parameters that have historically had
large gradients and left larger for parameters with small, infrequent gradients. It tracks both a
first moment estimate (like momentum) and a second moment estimate (an exponentially-weighted
average of squared gradients), applies a bias correction to both because they start at zero, and
divides the step by the square root of the second moment so that per-parameter step size adapts
automatically (Kingma and Ba,
[*Adam: A Method for Stochastic Optimization*](https://arxiv.org/pdf/1412.6980),
ICLR, 2015). Adam is the default optimizer for most deep learning workloads today because it
converges reliably with comparatively little manual learning-rate tuning, though plain SGD with
momentum and a well-tuned schedule can still generalize slightly better on some large-scale vision
tasks.

**Learning rate schedules.** The learning rate η controls how large each update step is; too high
causes the loss to oscillate or diverge, too low wastes compute converging slowly (chapter 1.8
covered this same tradeoff for a single gradient-descent step). A schedule changes η over the
course of training rather than fixing it: step decay drops η by a fixed factor every N epochs,
cosine annealing smoothly decreases η following a cosine curve toward a minimum, and warm-up
gradually increases η from near zero over the first several hundred steps before the main schedule
takes over, which stabilizes early training when a network's weights are still close to their
random initialization and large steps are more likely to diverge.

```python
import numpy as np

def adam_step(theta, grad, m, v, t, lr=0.001, beta1=0.9, beta2=0.999, eps=1e-8):
    """One Adam update step. m and v are the running first/second moment estimates."""
    m = beta1 * m + (1 - beta1) * grad
    v = beta2 * v + (1 - beta2) * (grad ** 2)
    m_hat = m / (1 - beta1 ** t)   # bias correction: m, v start at 0
    v_hat = v / (1 - beta2 ** t)
    theta = theta - lr * m_hat / (np.sqrt(v_hat) + eps)
    return theta, m, v

theta, m, v = np.array([0.5]), np.array([0.0]), np.array([0.0])
for t in range(1, 6):
    grad = np.array([2 * theta[0]])   # gradient of a toy loss L(theta) = theta^2
    theta, m, v = adam_step(theta, grad, m, v, t)
print(theta)  # theta moves toward 0, the minimum of L(theta) = theta^2
```
