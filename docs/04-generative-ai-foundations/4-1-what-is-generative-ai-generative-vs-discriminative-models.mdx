## TL;DR

Chapter 1.2 introduced generative AI as one layer in the AI taxonomy: systems that produce new content
rather than a label. This chapter opens up what "generative" actually means mechanically. A
**discriminative model** learns a direct mapping from input to output, typically approximating P(label
given input), and never represents how the input data itself was produced. A **generative model**
instead learns, explicitly or implicitly, something about the distribution the data itself came from,
which is what lets it sample new, never-before-seen examples rather than only label existing ones. This
single distinction is why a discriminative fraud classifier can tell you a transaction looks suspicious
but cannot produce a new synthetic transaction, while a generative model can produce entirely new text,
images, or data that never previously existed. Generative models further split into **explicit-density**
models, which compute a real probability for each output they produce (an autoregressive LLM, covered
in Phase 3), and **implicit-density** models, which learn only to sample convincingly without ever
computing an explicit probability (a GAN, covered in the next chapter). No single generative model
family available today gets high sample quality, full coverage of the data's diversity, and fast
sampling all at once, a tension known as the generative learning trilemma, which is why chapter 4.2
covers several structurally different families rather than one dominant approach.

## High-Level Explanation

Think of a discriminative model as a security guard checking IDs at a door: shown a person and a photo,
the guard can say whether they match, drawing on a learned sense of what matching looks like, but the
guard was never trained to draw a new face from scratch. A generative model is the sketch artist who
has studied enough faces to draw an entirely new, plausible one that never existed, because the artist
learned something about the underlying structure of faces themselves, not just a yes/no matching rule.
Both jobs can look similar from a distance, both involve faces, both produce a kind of judgment or
output, but only one of them can create something new. What determines which capability a model has is
not its architecture alone but what it was actually trained to predict: a model trained to predict a
fixed label learns to discriminate; a model trained to predict (or implicitly capture) the data itself
learns to generate.

## Deep-Dive Explanation

**The mathematical distinction, stated precisely.** A discriminative model directly parameterizes
P(y given x), the probability of a label given an input, or a direct function mapping input to output,
with no representation of P(x) itself anywhere in the model. A generative model parameterizes something
about the data's own distribution: classically, the joint distribution P(x, y), from which P(y given x)
can be derived via Bayes' theorem (1.8) if needed, or, in modern generative AI, the conditional
distribution P(output given input) treated as a full distribution to sample from rather than a single
predicted label. Naive Bayes (1.5) is the standard textbook generative classifier: it models P(x given
y) and P(y) separately, then combines them, which is also what lets it generate a synthetic x for a
given class if asked, a capability logistic regression, a purely discriminative model, does not have
even though both can be used for the same classification task.

**Explicit-density versus implicit-density generative models.** Among generative models, a further split
matters operationally. An **explicit-density** model computes a real, well-defined probability for each
output it could produce. An autoregressive language model (3.3) is explicit-density: at each generation
step it computes an actual probability distribution over every possible next token, and the model's
perplexity (3.3) is a direct, auditable summary of those probabilities. An **implicit-density** model
never computes any such probability at all; it learns only to produce samples that are hard to
distinguish from real data, typically by training one network to generate samples and a second network
to try to tell them apart from real data, with no explicit density anywhere in the setup. A Generative
Adversarial Network, covered fully in chapter 4.2, is the standard implicit-density example. This
distinction matters beyond theory: an explicit-density model's output can in principle be interrogated
for how confident the model actually was; an implicit-density model's output cannot, because there was
never a probability computed to interrogate in the first place.

**The generative learning trilemma.** Xiao, Kreis, and Vahdat ([*Tackling the Generative Learning
Trilemma with Denoising Diffusion GANs*](https://arxiv.org/abs/2112.07804), 2022) name a tension that
runs across generative model families: high-quality samples, full coverage of the data distribution's
diversity, and fast sampling are three goals that no single family achieves simultaneously with the
methods available at the time of that paper. GANs typically sample in a single fast pass and can produce
sharp, high-quality samples, but are prone to **mode collapse**, a failure mode where the generator
learns to reliably produce only a narrow subset of the true data's variety, sacrificing diversity.
Variational autoencoders (VAEs) sample quickly and tend to cover the data's diversity well, but their
samples are often blurrier or lower-fidelity than a GAN's. Diffusion models, covered in chapter 4.2,
typically achieve both high sample quality and good diversity, but pay for it with slow sampling, since
generating one sample requires many sequential denoising steps. Naming this trade-off explicitly, rather
than treating any one family as strictly "better," is what lets a practical choice among generative
model families in chapter 4.2 be a genuine engineering trade-off rather than a search for one universally
superior option.
