## TL;DR

Chapter 3.1 introduced tokenization as a pipeline step without specifying how a tokenizer actually
builds its vocabulary. This chapter covers the three subword segmentation algorithms behind nearly
every production tokenizer in use today. **Byte Pair Encoding (BPE)** starts from individual
characters (or bytes) and repeatedly merges whichever adjacent pair occurs most frequently in the
training corpus, a purely frequency-driven, bottom-up process; GPT-family models use a byte-level
variant that guarantees any input string is encodable with no unknown-token fallback ever required.
**WordPiece** follows the same bottom-up merge structure as BPE but scores each candidate merge by
how much it increases the training corpus's likelihood rather than by raw frequency alone, and is the
tokenizer BERT uses. **SentencePiece** is a tokenizer framework, not a single algorithm: it treats
input as a raw stream of characters, including whitespace as an ordinary symbol, which makes it
language-independent, and it can run either BPE-style merging or a genuinely different algorithm,
the Unigram language model tokenizer, which starts from a large candidate vocabulary and prunes it
down rather than building it up. T5, mT5, ALBERT, and XLNet use SentencePiece. The choice between
these algorithms is rarely visible to a model's end user, but it shapes vocabulary size, sequence
length, out-of-vocabulary robustness, and multilingual behavior in ways that matter operationally.

## High-Level Explanation

Think of building a subword vocabulary like designing a set of building blocks for constructing
words. Full common words make efficient blocks, but a vocabulary of only whole words runs into rare
or novel words it has never seen and cannot build. Subword tokenizers solve this by keeping a mix of
block sizes: common whole words stay as single blocks, while rare or unfamiliar words get built out of
smaller, more common pieces, so nothing is ever unbuildable. The three algorithms in this chapter
differ mainly in **how they decide which blocks belong in the set**. BPE and WordPiece both start
from the smallest possible blocks (individual characters) and repeatedly glue two blocks together into
a bigger one, working their way up: BPE glues together whichever pair shows up most often, and
WordPiece glues together whichever pair most improves how well the resulting vocabulary explains the
training text. SentencePiece is a different kind of choice: it is the framework that decides whether
spaces are treated as an ordinary character (so tokenization is fully reversible and doesn't need to
know where words start and end ahead of time), and inside that framework, the actual block-choosing
algorithm can be BPE, or it can be the Unigram algorithm, which works in the opposite direction, from
a large set of candidate blocks down to a smaller, final set.

## Deep-Dive Explanation

**BPE's merge algorithm, mechanically.** BPE (Sennrich et al.,
[*Neural Machine Translation of Rare Words with Subword Units*](https://arxiv.org/abs/1508.07909),
2016) starts by splitting every training word into individual characters and counting every adjacent
symbol pair across the entire corpus. It then merges the single most frequent pair into one new
symbol, adds that symbol to the vocabulary, and recounts pairs in the now-updated corpus. This merge
step repeats until the vocabulary reaches a target size, commonly tens of thousands of entries. Each
merge is chosen purely by frequency, with no notion of what a merge means linguistically: two
characters that happen to co-occur often, whether or not they form a meaningful unit, get merged
before a rarer but more meaningful pair does. GPT-2 (Radford et al., 2019) introduced **byte-level
BPE**, which runs this exact merge algorithm over raw UTF-8 bytes rather than Unicode characters. Because
there are only 256 possible starting bytes, byte-level BPE has a complete, fixed starting alphabet, so
every possible input string, including one containing a character never seen during tokenizer
training, can always be encoded as some sequence of byte-level tokens. This eliminates the
out-of-vocabulary problem entirely: there is no unknown-token fallback because none is ever needed.

**WordPiece's scoring change, and why it produces a different vocabulary from the identical corpus.**
WordPiece (Schuster and Nakajima, 2012; adopted by BERT) uses the same bottom-up merge structure as
BPE, characters up to larger units, but changes the criterion for choosing which pair to merge next.
Instead of picking the most frequent adjacent pair, WordPiece picks the pair whose merge most
increases the likelihood of the training data under a language model built from the resulting
vocabulary, which in practice reduces to preferring a pair whose joint frequency is high relative to
the product of each symbol's individual frequency, a criterion closer to pointwise mutual information
than to raw frequency. Two symbols that each appear often on their own, but rarely appear together,
score lower under WordPiece than two rarer symbols that almost always appear together, even if the
first pair's raw joint frequency happens to be numerically higher. Run on the same training corpus,
BPE and WordPiece can therefore converge on different final vocabularies, because they are optimizing
different objectives at every single merge step, not because either implementation is buggy or
approximate.

**SentencePiece: why whitespace-as-a-symbol matters, and the Unigram algorithm it also supports.**
SentencePiece (Kudo and Richardson,
[*SentencePiece: A Simple and Language Independent Subword Tokenizer and Detokenizer for Neural Text
Processing*](https://arxiv.org/abs/1808.06226), 2018) treats an entire input string as a raw sequence
of characters, replacing every space with a reserved meta-symbol (commonly rendered as "▁") rather
than using whitespace to pre-split the input into words before tokenizing. This makes tokenization
fully reversible; the original text, including its exact spacing, can be reconstructed from the token
sequence alone, and it makes the same tokenizer usable on languages like Japanese or Chinese that do
not mark word boundaries with whitespace at all, with no separate language-specific pre-tokenizer
required. SentencePiece is a framework in the sense that it can run either BPE merging internally, or
a separate algorithm called the **Unigram language model tokenizer** (Kudo,
[*Subword Regularization: Improving Neural Network Translation Models with Multiple Subword
Candidates*](https://arxiv.org/abs/1804.10959), 2018). Unigram works in the opposite direction from
BPE and WordPiece: it starts from a large candidate vocabulary of possible subwords and iteratively
removes whichever tokens contribute least to the training corpus's overall likelihood, using an
expectation-maximization procedure, until the vocabulary shrinks to the target size. Because it treats
segmentation probabilistically rather than as one fixed set of merge rules, Unigram can also assign
probabilities to multiple different valid segmentations of the same input string, which enables
**subword regularization**: sampling a different valid segmentation of the same training example on
different training passes, which exposes a model to more segmentation variety and can improve
robustness to unusual or noisy input at inference time. T5 and mT5 use SentencePiece with the Unigram
algorithm; ALBERT and XLNet use SentencePiece as well.
