## TL;DR

Chapter 3.3 covered three language modeling objectives in the abstract. This chapter covers the
actual model families each objective produced, and how each family evolved. **GPT** is a
decoder-only architecture built on causal language modeling, evolving from GPT-1's proof that
pretraining plus fine-tuning works for generation, through GPT-2 and GPT-3's discovery that scale
alone unlocks zero-shot and few-shot task transfer, to GPT-4's multimodal, alignment-tuned form.
**BERT** is an encoder-only architecture built on masked language modeling, evolving through RoBERTa
(more data and compute, a dropped auxiliary objective), ALBERT (parameter-sharing for efficiency),
and DeBERTa (a refined attention mechanism), all aimed at stronger fixed-input understanding rather
than generation. **T5** and **BART** are encoder-decoder architectures built on seq2seq objectives,
converging on the idea that every task, including classification, can be framed as generating text
from text. The architecture a team picks is rarely a free choice, it is largely determined by which
of these three families' pretraining objective matches the task.

## High-Level Explanation

Think of GPT, BERT, and T5 as three family trees, each rooted in one of chapter 3.3's three
objectives, each growing over several years of research. The GPT family keeps only a decoder: no
separate encoder module exists, so a GPT-style model reads a prompt and continues it, using the same
causal, one-direction-only mechanism for understanding the prompt and generating the reply. The BERT
family keeps only an encoder: it produces rich, bidirectional representations of a fixed input, but
has no decoder and therefore no built-in mechanism to generate new text, only to output predictions
(a class label, a span, a masked-token guess) through a task-specific head added on top. The T5 and
BART family keeps both halves, an encoder that reads the full input and a decoder that generates a
separate output, which is why this family fits transformation tasks (translate this, summarize this)
most naturally.

## Deep-Dive Explanation

**The GPT family's progression, and what scale actually unlocked at each step.** GPT-1 (Radford et
al., [*Improving Language Understanding by Generative Pre-Training*](https://openai.com/research/language-unsupervised),
2018) demonstrated that a decoder-only Transformer pretrained with causal language modeling, then
fine-tuned on a labeled task, beat prior task-specific architectures. GPT-2 (Radford et al.,
[*Language Models are Unsupervised Multitask Learners*](https://openai.com/research/better-language-models),
2019, 1.5B parameters) showed that a large enough causal LM could perform many tasks in a **zero-shot**
setting, from a task description in the prompt alone, with no fine-tuning step at all. GPT-3 (Brown
et al., [*Language Models are Few-Shot Learners*](https://arxiv.org/abs/2005.14165), 2020, 175B
parameters) went further: providing a handful of input-output examples directly in the prompt
(**in-context learning**, or few-shot prompting) let the model adapt to a new task's format without
updating any weights at all, a capability that scaled model size made dramatically stronger without
any change to the underlying causal LM objective. GPT-4 (OpenAI,
[*GPT-4 Technical Report*](https://arxiv.org/abs/2303.08774), 2023) added multimodal input and
large-scale reinforcement learning from human feedback (RLHF) for alignment, covered in Phase 7,
without abandoning the decoder-only, causal-LM foundation. Chapter 3.6 covers why scale specifically
produces new capabilities like this rather than just smoothly improving existing ones.

**Why decoder-only models can be prompted directly, mechanically.** Because a GPT-style model has no
separate encoder, the prompt and the generated continuation live in the exact same token sequence,
processed by the exact same causal self-attention stack. When the model generates the first token of
its answer, it is already attending back over every token of the prompt, the same mechanism it uses to
attend over its own previously generated tokens. There is no architectural seam between "reading the
prompt" and "writing the answer," which is precisely what makes in-context learning possible: the
few-shot examples in the prompt are just more prior tokens the causal attention mechanism conditions
on, with no separate training step required to make use of them.

**The BERT family's progression: refining understanding, not adding generation.** RoBERTa (Liu et al.,
[*RoBERTa: A Robustly Optimized BERT Pretraining Approach*](https://arxiv.org/abs/1907.11692), 2019)
kept BERT's architecture and masked language modeling objective, but trained on roughly ten times more
data for longer, dropped the next-sentence-prediction objective (3.3) after finding it unhelpful, and
switched to dynamic masking (choosing which tokens to mask fresh each epoch rather than once during
data preprocessing), improving downstream results without any architectural change. ALBERT (Lan et al.,
[*ALBERT: A Lite BERT for Self-supervised Learning of Language Representations*](https://arxiv.org/abs/1909.11942),
2019) instead changed the architecture for efficiency: it shares the same parameters across every
Transformer layer (rather than each layer having its own independent weights) and factorizes the
embedding matrix into two smaller matrices, substantially shrinking parameter count with a smaller
accuracy cost than the size reduction would suggest. DeBERTa (He et al.,
[*DeBERTa: Decoding-enhanced BERT with Disentangled Attention*](https://arxiv.org/abs/2006.03654),
2020) changed the attention mechanism itself: **disentangled attention** represents each token with
two separate vectors, one for content and one for relative position, and computes attention weights
from both separately rather than from a single combined vector, which more precisely captures how
much a word's relevance depends on its position relative to another word versus its content alone.

**The T5/BART family: two different pretraining recipes converging on encoder-decoder.** T5's
pretraining objective (3.3) is span corruption: contiguous spans of the input are replaced with a
single sentinel token, and the decoder must generate just the missing spans, not reconstruct the whole
input. BART (Lewis et al., [*BART: Denoising Sequence-to-Sequence Pre-training for Natural Language
Generation, Translation, and Comprehension*](https://arxiv.org/abs/1910.13461), 2019) instead trains
as a **denoising autoencoder**: it corrupts the input with a mix of noise functions (token masking,
token deletion, text infilling, sentence permutation, document rotation) and the decoder must reconstruct the entire
original, uncorrupted document, not just the missing pieces. Both use an encoder-decoder architecture,
so both fit the same "read input fully, generate output" shape from 3.3, but BART's decoder generates
whole documents during pretraining while T5's generates only short missing spans, a training-time
difference each paper's own ablations connect to different downstream strengths (BART edges ahead on
some pure generation and summarization benchmarks; T5's controlled, unified text-to-text framing made
it a common basis for later multi-task and instruction-tuned models). mT5 (Xue et al.,
[*mT5: A Massively Multilingual Pre-trained Text-to-Text Transformer*](https://arxiv.org/abs/2010.11934),
2021) applies T5's identical architecture and objective to a corpus covering 101 languages, changing
only the training data and the shared multilingual vocabulary, not the underlying mechanism.
